# 08 — Browser UI

React + Vite single-page app, served by the server. Design goal: an operator's console that is pleasant to leave open on a second monitor for days, plus a replay viewer that makes any game readable in under a minute.

## Pages

1. **Runs** — table of runs with status, cycle, win-rate sparkline (A vs B over cycles), games/sec, last change. Actions: new run, start/pause/stop, fork, export/import.
2. **New run** — settings form (defaults per 05), seed-deck mode (constrained random with a "roll" preview showing the 75 with images and support status, or paste a decklist which is validated card-by-card), initial ban list (optional, can paste a list).
3. **Run dashboard** — the heart of the app:
   - header: status, cycle, progress bar for the current cycle, live game/sec;
   - **win-rate chart** over cycles for both agents, with markers where changes and bans happened;
   - **current decks** side by side: main and side, grouped by type, mana curve, colour pie; each card shows its Δ statistic as a coloured chip; hover shows the card image (Scryfall) and its full statistics;
   - **timeline**: every cycle as a row: result, loser, the change in words ("Cut X for Y — reason"), with a diff view and a link to the cycle detail;
   - **ban console** (always visible on this page): search any Scryfall card, mark banned/restricted with a note; current list with history; the UI shows immediately which agent is affected and, after the current game, the legalisation change that resulted.
4. **Cycle detail** — matches table (winner, games, sideboarding plan), stats table (sortable by any statistic, per agent, filterable to main/side), the change with its evidence (candidate shortlist and trial results), and links into each game.
5. **Game viewer** — replay and live share one renderer:
   - board: both players' battlefields (lands row, creatures row, other permanents row), hands (yours visible, opponent's face-down by default with a "reveal hidden info" toggle since the log contains it), graveyards/exile as stacks with counts and expandable lists, stack panel, life/poison/mana pool, turn/step indicator, and planeswalker loyalty;
   - transport: play/pause, step forward/back by event or by turn, speed 0.25×–8×, scrub bar with turn markers; keyboard shortcuts;
   - event ticker: human-readable play-by-play ("A casts Lightning Bolt targeting Tarmogoyf", "B responds with Counterspell"), with the AI's evaluation score shown as a small bar so you can see why it did that;
   - live mode: attaches to the run's current game, auto-follows new games, with a "pin this game" control;
   - card hover anywhere shows the card image and oracle text; unsupported/partial scripts are never in games, but the coverage page uses the same component.
6. **Cards & coverage** — search all of Scryfall with support status; parser coverage totals; the most-requested unsupported cards (with the failing sentence highlighted) so hand-scripting effort follows demand; a "try to script" button.
7. **Settings** — workers, retention, image cache, spectator pacing.

## Rendering

The board renderer consumes `GameEvent`s and maintains its own lightweight view model (it does not run the engine), applying events forward and using per-turn snapshots for fast backward scrubbing — kept by the viewer as it folds, not embedded in the log (ADR 0019). Animations are minimal: a short slide when an object changes zone, a flash on damage, a pulse on the stack; these can be turned off. Card frames are simple colour-coded boxes with name/cost/type/P-T text; art loads lazily via the image proxy and can be disabled for text-only mode.

State management: Zustand stores for the run list, the active run, and the viewer; TanStack Query for HTTP; a single WebSocket client with subscription reference counting.

## Accessibility and theme

Keyboard-operable transport and tables; light/dark theme; colour-blind-safe palette for agent A/B and for Δ chips (blue/orange rather than red/green, with sign glyphs).

## As built (6.3)

In `apps/web/src`, React 19 with TanStack Query and zustand, as above:

- **Shell**: a header with the pages, the server's health and whether the live feed is connected, and a history router of four routes — `/` (runs), `/runs/new`, `/runs/:id` (the dashboard since 6.4, which added `/runs/:id/cycles/:n`) and not found. The server answers `index.html` for any page path, so reloads and pasted links work.
- **HTTP**: every response is parsed with the schema the server's contract tests hold it to (`@mtg/shared` api.ts), so a field the two ends disagree about fails at the fetch, not three components later; errors show docs/07's message and code.
- **The socket**: one `LiveSocket`, opened at start. A component subscribes for as long as it is mounted; the server hears `subscribe` when the first component asks for a subscription and `unsubscribe` when the last lets go — which matters, since a run's games are streamed only while someone watches. It reconnects with backoff (0.5 s doubling to 10 s, reset by a good connection), subscribes again to all still wanted, hands each message only to the subscriptions it belongs to, and drops what it cannot read.
- **Runs**: status (a running run with no worker yet says it is waiting for one), cycle with the matches done of those planned and the time left, A's win rate over the last 40 cycles as a sparkline, games per second, the last change, and start/pause/stop as the status allows, fork at a finished cycle, export and import. The zustand runs store keeps each run's latest `runStatus`; a row shows it over the fetched summary when it is the newer of the two — a run paused while it waited for a worker sends no status, and the fetch after the pause is then what is true — and the list is fetched again when a status names a cycle or a status it does not know.
- **New run**: every setting, starting from docs/05's defaults read from the settings schema; the seed deck either rolled — the 75 as card images (a text frame when images are off or fail), with support status, the seed filled in so the run gets that deck, a warning when the seed, colours, lands, card pool or bans change after the roll, and a new seed on request — or pasted, parsed as it is typed (`@mtg/shared` `parseDecklist`: plain, `4x` and Arena exports, sideboard headers or a blank line, split cards), each name looked up once and checked: known, playable, sixty and fifteen, within the initial ban list, line by line; and the initial ban list, from a card search or pasted names, each banned or restricted with a note. The form will not submit while anything stops the run being made, and says what.
- **Tests** render the pages into happy-dom with a fake `fetch` and a fake socket and drive them as a person would; the socket client, the router, the store's merge and the paste checks have their own.

## As built (6.4)

- **Run dashboard** (`/runs/:id`): the header has the status, the cycle, a progress bar of the cycle's matches and the games per second while a worker plays it, with start/pause/stop and export. Below it:
  - **Win rates**: both agents over every cycle on one 0–100% axis with 50% drawn stronger; A is `#1b8fd0` and B `#e8672a`, checked colour-blind-safe against the dark surface (the dataviz palette validator: 22.6 ΔE under simulated colour-blindness, 31.1 in normal vision), with a legend, the lines labelled at their ends, and each change a dot on the changing agent's line in its colour. A ban is a hairline at the cycle it took effect in, read from its game stamp (`…:cycle-N:start`, `…:cycle-N:match-M:game-G`, or `…:created` for cycle 0). Pointer or arrow keys move a crosshair whose tooltip gives the cycle's rates, the loser, the change or why nothing changed, and its bans; the timeline is the chart's table.
  - **Decks** side by side: the main deck grouped by the front face's first type (Creature, Planeswalker, Battle, Land, Instant, Sorcery, Artifact, Enchantment), cheapest first, then the sideboard; a mana curve of the spells (0 to 7+) and the colours the costs ask for (hybrid counts both, Phyrexian its colour). Each card has its Δ as a chip — blue with ▲ for good, orange with ▼ for bad, in percentage points — and on hover or focus its image and full statistics. The statistics are docs/05's decayed roll-up, so counts are weighted and shown rounded with ≈.
  - **Timeline**: every cycle newest first, 50 at a time — result, loser, the change in words with the agent's colour, or why nothing changed — with a diff (`− 4 Shock (main)`, `+ 4 Chain Lightning (main)`) and a link to the cycle.
  - **Ban console**, beside the rest and sticky: the list with an unban for each; any card from a search, banned or restricted with a note, and before it is made, which agent it would catch and how many copies it must cut ("Agent A holds 4 and must cut to 0"); the edits still pending and when they take effect (after the game in progress, or when the run next plays); every legalisation a ban caused, as a diff; and the trail.
  - **Live**: `runStatus` updates the header; `cycleFinished` adds the cycle to the chart and timeline at once and refetches the run and the statistics; `deckChanged` refetches the decks (and the ban console, for a legalisation); `banApplied` refetches the ban console.
- **Cycle detail** (`/runs/:id/cycles/:n`): the result, the change with its evidence — the diagnosis, the deck's rates, the card cut with its Δ, and the shortlist of candidates with their scores and trials, the chosen one marked — or why nothing changed; each deck's rates and play/draw record; the matches; and a statistics table for the cycle, opening on the loser, sortable by any column (worst Δ first), filterable to main or side, switchable to the other agent.
- Cards are named, grouped and curved from `POST /api/cards/lookup` (docs/07), fetched once for a deck and kept.
- The dashboard is dark only, like the rest of the app; the light theme above is not built.

## As built (6.5)

- **Game viewer**: `/games/:id` replays a stored game; `/runs/:id/live` follows a run's games as they are played. Both are one renderer (`apps/web/src/viewer`), fed a `Replay` of events and the objects' identities.
  - **Rendering**: the board is the log folded to the transport's position (`@mtg/shared` replay.ts). The log carries no snapshots: the `Replay` keeps a board at the start of every turn as it folds, so any position is at most a turn's folding away (ADR 0019). Cards are text frames — name, counters, loyalty, power/toughness (printed plus +1/+1 and -1/-1 counters), damage marked, tapped (turned and dimmed), attacking (⚔) or blocking (⛨) — with B at the top and A at the bottom, creatures nearest the middle. A permanent sits on its owner's side, since control changes are not logged. Animations are a pulse on the top of the stack and a flash on damage, off with a switch or the system's reduced-motion setting; the slide on a zone change is not built.
  - **Hands**: A's is face up, B's face down until "Reveal hidden information", which also names what B draws in the ticker.
  - **Transport**: start, previous and next turn, previous and next event, play/pause, end; speed 0.25×–8× (a told event every 800 ms at 1×); a scrub bar with each turn marked and clickable. Stepping "by event" steps by what the ticker tells — a told event is shown with what followed it untold, so "A casts Goblin Guide" shows the spell on the stack and the land that paid for it tapped. Keys: Space or K play and pause, ← → by event, Shift+← → or [ ] by turn, Home and End, + and − speed, H reveal, T art, L go live; they work anywhere but in a text field, and leave the scrub bar its own arrows.
  - **Ticker**: the game in words — "B responds with Pyroblast targeting Chain Lightning", "Goblin Guide dies", "B wins on life" — with steps, taps, priority and mana abilities left out, the past in full and the rest dimmed, each line a place to go. An action carries the deciding player's evaluation as a bar about zero (blue + good for them, orange − not), scaled to the game's 90th percentile so one won position does not flatten the rest.
  - **Hover card**: on hover or focus, anywhere on the board, the card's image through `/img` and its oracle text, type and cost, with what the board says of it now; text alone with "Card art" off or when the image will not load. Faces come from `POST /api/cards/lookup` (docs/07).
  - **Live**: it follows the newest event (Go live after stepping away) and each new game unless "Pin this game" is on, keeping the last eight games and the pinned one however many follow, with how many have; a recent game can be picked and played back. The simulation does not wait: the page keeps every event and plays them at the viewer's speed.
- **Links**: the dashboard's "Watch live"; the cycle page's matches open to their games, each "Watch the replay" when its log was kept.
- **Found in a real browser against a real run**: the opening hands' draws filled the ticker (dealing is now told by the keep), "A chooses A to play first" (now "A chooses to play first", or "B chooses to draw, so A plays first"), every spell "with X = 0" (the engine now logs X only for a spell cast with one), the transport's keys dead after clicking a switch, score bars flattened by one won position, and — the one that mattered — a pinned game dropped while it was watched, because greedy games are quick enough for eight more to start in a second and a half.

## As built (6.6)

- **Cards & coverage** (`/cards`, and `/cards/:oracleId` with a card open), in the header as "Cards":
  - **Totals**: the share of Scryfall the parser scripts in full, from the last `pnpm cards:coverage` report, as one bar split by verdict (supported, partial, unsupported, unscripted — the support badges' colours, each with its glyph, count and share), the sentences read, and when it was measured if the report says (a file's own date only says when it was copied); and what this server's script cache holds. With no report, the page says how to make one.
  - **Most requested, and what stopped them**: the cards runs asked for and could not have, most asked first, each with its first unread sentence marked — underlined, tinted and prefixed ✕ "Not read", not colour alone — or the reason it was refused, and "Try to script", which scripts it again and says how it came out. A run asking for a card it cannot have (`unsupportedCard` on the socket) fetches the list again.
  - **Templates to teach next**: the report's failing patterns, ranked by the cards each would finish rather than by how often it appears, with an example.
  - **Search** every card by name, type or rules text (from two letters, a quarter of a second after typing stops), each with its support; opening one shows its image, cost and type, its rules text a sentence at a time marked read (✓) or not read (✕), or neither with no script, the script's findings, its record across runs and "Try to script".
- **Found in a real browser against the real server**: the report's date was the file's — in a checkout, when it was cloned — so `pnpm cards:coverage` now writes `measuredAt` and the page shows no date for a report without one; and the Docker image did not ship the report, so it does now.

## Out of scope for v1

Human play, mobile layout polish, multi-run comparison views (planned later), deck editor beyond paste.
